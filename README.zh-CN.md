# TimeCue

[English](README.md) | [简体中文](README.zh-CN.md)

会报时的训练计时器，支持计时组、计次组、组间休息和训练日历，让你专注动作，无需频繁看屏幕。适合跳绳、悬挂、平板支撑、卧推等训练。完成的 Session 可保存到本地，并通过 JSON 备份历史。当前版本使用英文界面与英文语音。

**在线使用：** https://omegazhang3.github.io/voice-timer/

**后续计划：** [TimeCue TODO](TODO.md)，首要待办为语音控制 Start / Stop。

## 功能亮点

- **定时语音报时**：按预设或自定义间隔播报已用时。简洁模式只报秒数，例如“5 seconds”“10 seconds”。
- **准备倒计时**：支持 3、5、10 秒语音倒计时，也可关闭，方便先准备好姿势；默认 3 秒。
- **灵活控制计时**：支持开始、暂停、继续和停止，准备倒计时与暂停时间不计入训练时长。
- **掌握组间休息**：Stop 后独立显示已休息时长，保存、修改 Set 和下一组准备倒计时期间持续累计，不影响主计时、报时间隔及训练总时长。
- **分组训练记录**：为 Session 命名，如“跳绳”“悬挂”，每段停止后的计时可手动保存为一组 Set。
- **力量训练计次**：卧推、深蹲等按次数记录的动作可选择 **Reps**，在 Save set 前输入完成次数；次数和计时时长分别汇总。
- **快速修正时长**：减少时跳到前一个 5 秒整倍数，例如 47→45→40；增加时每次加 1 秒，最高不超过实测时长。
- **训练汇总**：Saved sets 和最终汇总显示每组时长及 **Rest after** 间隔。下一组正式开始时，自动将间隔记录在前一组上，休息时间独立于训练总时长。
- **训练日历与备份**：将已完成的 Session 保存到指定日期，查看每日训练和 Set 明细，支持 JSON 导出、导入备份。历史使用 IndexedDB 保存在当前浏览器。
- **轻量易用**：手机或电脑浏览器直接打开，无需安装或注册。当前训练在点击 Save to calendar 前仍为临时记录；计时偏好单独保存。

## 快速开始

1. 为 Session 命名，在 **Record set as** 中选择 **Time**（计时）或 **Reps**（计次）。
2. 每组使用 **Start / Stop**，调整时长或输入次数后点击 **Save set**。组间休息自动累计。
3. 训练完成后，依次选择 **Finish session → Training date → Save to calendar**。仅点击 Save set，记录仍只保留在当前 Session 中。
4. 在 **Training calendar** 中点击日期，查看已保存的训练与 Set 明细。使用 **Export JSON** 备份，或用 **Import JSON** 恢复、迁移历史；已有相同 ID 的 Session 会跳过。

同一浏览器刷新后仍可查看日历历史。New session 清除当前汇总，不会删除日历记录。

## 计时与语音选项

- 正向累计计时，使用英文播报，例如“1 minute 30 seconds elapsed”。
- 报时间隔预设为 5、10、30、60 秒，也可自定义为 5 至 3,600 秒之间的整数。
- **Short announcements** 开启简洁播报，只报累计秒数，例如“5 seconds”“10 seconds”“65 seconds”，不加“elapsed”。可随时切换；**Test voice** 按当前模式与间隔试听语音。
- 支持开始、暂停、继续和停止；停止后的时长保持显示，直到再次开始或离开、刷新页面。
- **Start delay** 可选 Off、3、5、10 秒，默认 3 秒。每次新计时开始前显示大字倒计时并语音播报，以“Go!”提示正式开始。可随时取消准备倒计时；准备时间不计入已用时，也不计入报时间隔。暂停后继续不会再次倒计时。
- 暂停时间不计入已用时。计时过程中报时间隔设置会锁定。
- 可在开始前试听语音；关闭准备倒计时后直接开始，以及暂停后继续时，会播放简短语音确认。
- 浏览器保存报时间隔、准备倒计时和播报模式偏好，无需账户或后端服务。
- 页面适配手机与电脑屏幕。

## Session 与 Set

Session 表示一次训练，Set 表示其中一组计时。可以手动创建并命名 Session，名称支持中文；也可直接开始计时，应用会使用已填写的名称或当前日期时间自动创建 Session。Time 模式下每组停止后，可先用 **Set duration** 的 **− / +1** 按钮调整时长，再点击 **Save set** 保存。例如，实测 20 秒可减少为 15 秒，再逐秒加回 20 秒，但不能超过 20 秒。原始实测时长仍会显示，Session 统计使用调整后的保存值。未保存的时长不计入总时间，同一组不能重复保存。

点击 **Next set** 可沿用当前报时与准备倒计时设置开始下一组。如果还有未保存的 Set，开始下一组或结束 Session 时，会提示保存、丢弃或继续编辑。Session 进行期间，可通过 **Delete** 删除已保存的组。

停止计时后，点击 **Finish session** 查看每组记录、总组数和累计时长。Set 时长默认为计时器显示的完整秒数。减少按钮跳到前一个 5 秒整倍数，例如 47→45→40、41→40；增加按钮每次加 1 秒，最多恢复至原始实测时长。如果下一步会超过实测时长或低于 1 秒，对应按钮会禁用。实测 5 秒及以下的组保持原始时长，Time 模式下不足 1 秒的计时不生成待保存记录。准备倒计时、暂停、组间休息和丢弃的组不计入累计时长。

当前 Session 暂存在页面内存中，完成后需要点击 **Save to calendar** 才会持久保存；仅点击 Save set 或 Finish session 不会写入历史。刷新或关闭页面会清空当前训练，但已保存到日历的历史仍保留在 IndexedDB 中。当前 Session 尚未保存到日历时，应用会请求浏览器在离开前提示，部分手机浏览器可能不显示提示。新建 Session 时，如果上一轮包含未保存到日历的 Set，会要求确认；新建操作不会清空日历历史。计时偏好仍单独保存。

## 按次数记录力量训练

对于卧推等按次数记录的动作：

1. 将 **Record set as** 设为 **Reps**。也可以在 Stop 后，将尚未保存的 Set 从 Time 切换为 Reps。
2. 仍使用 Start 和 Stop 标记每组开始与结束，以准确记录组间休息。准备倒计时、计时和暂停期间，记录类型会锁定。
3. Stop 后，在 **Reps completed** 中输入完成次数，例如 `8`，再点击 **Save set**。只接受正整数，空值、0、负数和小数无法保存。

Reps 模式保留准备倒计时和开始、继续时的语音确认，关闭已用时的定时播报。计时器仍显示已用时供参考，但该时长不加入已保存计时组的总时长。每组的次数输入框重新置空，次数不受实测秒数限制。Time 模式沿用原有的时长调整规则。

Saved sets 的 **Result** 列显示 **8 reps**，同时保留 **Rest after**。同一 Session 可以混合计时组与计次组：例如 8 次、20 秒、10 次三组，分别汇总为 **3 组**、**计时组时长 00:20**、**总次数 18**。如果全部为计次组，结束后的大字汇总显示总次数。保存或丢弃提示、删除功能均支持两种记录类型。所选类型仅在本次页面访问中保留。将完成的 Session 保存到日历后，次数和其他 Set 明细可以在刷新后继续查看。

## 组间休息计时

停止一组后，独立的 **Rest time** 显示会自动从零开始累计休息时间，同时保留主计时的最终时长。保存、修改、删除或丢弃 Set 不会重置休息计时；打开保存或丢弃提示窗口时，休息计时也会继续。

下一组正式开始时结束休息计时，因此下一组的准备倒计时计入休息时间。取消准备倒计时后，仍沿用当前休息计时。第一组开始前不会显示休息计时，组内暂停也不会启动休息计时。每组正式计时后点击 Stop，开始一段新的休息计时。结束 Session 会清除休息显示，新 Session 从头开始。

休息时间仅在界面显示，不进行语音播报，不改变主计时报时间隔，也不计入 Set 时长和 Session 训练总时长。

Saved sets 和 Session 汇总中的 **Rest after** 列将已完成的间隔记录在前一组上：例如 Set 1 停止后 10 秒正式开始 Set 2，Set 1 的间隔显示为 **00:10**。下一组正式开始时自动确定该间隔，包含准备倒计时及保存、编辑记录所用的时间。修改 Set 时长不会改变休息起点。下一组尚未开始时显示 **—**；直接结束 Session 时，最后一组没有后续间隔。不足 1 秒的间隔显示为 **00:00**。删除或丢弃一组也会移除它对应的间隔记录，不会把间隔转移或合并到其他组。

例如：保存计时 20 秒的 Set 1，休息 10 秒后正式开始 Set 2，再保存计时 15 秒的 Set 2 并结束 Session：

| Set | 时长（Duration） | 后续间隔（Rest after） |
| --- | --- | --- |
| Set 1 | 00:20 | 00:10 |
| Set 2 | 00:15 | — |

汇总显示 **2 组**、**总时长 00:35**。10 秒间隔记在 Set 1 上，不计入总时长。Set 时长仍需手动保存；间隔完成后自动补充，无需再次点击 Save set。结束 Session 后点击 Save to calendar，可保留这些记录及组间间隔。

## 训练日历与 JSON 备份

1. 完成各组训练，点击 **Finish session**。
2. 检查 **Training date**，点击 **Save to calendar**。默认使用 Session 开始时的本地日期，即使跨午夜结束也不会自动换日。可选择其他日期补记；空 Session 无法保存。
3. 使用月历的前后箭头或 **Today**，点击某一天。有记录的日期显示圆点和 Session 数量。展开 Session 可查看每组的结果、实测时长及 Rest after。每日与 Session 汇总分别统计时长和次数。

重复保存同一个已完成的 Session 使用同一 ID，不会生成重复记录。在当前已完成 Session 仍打开时，修改 Training date 并点击 **Update calendar date** 可移动该记录。**Delete session** 经确认后删除日历中的记录。日历操作不改变当前计时器或当前 Session 的 Set。

**Export JSON** 导出全部日历记录。**Import JSON** 接受 TimeCue 第 1 版 JSON 备份，导入前预览新增和已存在的 Session 数量，再确认写入。已有相同 ID 的记录会跳过，即使内容不同也不会覆盖。整份文件通过校验后，所有新增记录在同一个事务中导入；无效文件或写入失败不会破坏已有历史。备份包含格式版本、稳定的 Session ID、名称、归属日期、开始与保存时间、原始时区，以及全部 Set 明细；汇总数据从明细计算。在其他时区导入时，归属日期保持不变。

历史使用 **IndexedDB** 保存在本地浏览器，无需账号、后端服务，也不会上传 GitHub。数据属于当前浏览器配置及网站来源；其他浏览器、设备或网站域名拥有各自独立的存储。清理网站数据、结束隐私浏览或浏览器回收存储，都可能导致历史丢失，请保留 JSON 备份用于恢复或迁移。存储异常会显示提示，可使用 **Retry / refresh** 重试；历史存储不可用时，计时器和当前 Session 仍可使用。当前不自动保存未完成的 Session，也不进行云端同步。

## 本地运行

在项目目录启动静态 HTTP 服务，例如：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

打开 http://localhost:8000。应用使用 JavaScript 模块，请通过 HTTP/HTTPS 访问，不要直接打开 `index.html`。本地运行无需安装依赖或构建。

## GitHub Pages 部署

每次推送到 `main` 分支，`.github/workflows/pages.yml` 工作流都会运行测试，并执行 `npm run build` 构建静态站点。仓库 Settings → Pages → Source 需设为 **GitHub Actions**。

构建会在 `dist/` 中为 JavaScript、CSS 和图标生成包含内容哈希的文件名。应用会导入版本匹配的计时、Session、日历及历史模块，避免新界面使用不匹配的缓存代码。本地开发仍可直接通过静态服务器运行源文件。

## 语音与计时说明

语音使用浏览器 Web Speech API 和设备提供的英文语音。可用声音、音质及是否需要联网取决于浏览器与语音服务提供方。应用不请求麦克风权限。如果语音不可用，页面会说明原因，计时器仍可使用。

已用时根据单调时钟的时间差计算，不依赖回调次数累加。页面延迟更新时，只播报一次当前已用时，不补播错过的报时。暂停或停止会取消语音。

当前版本专注前台计时，暂不包含后台或锁屏报时、保持屏幕常亮、PWA 安装和语音指令。刷新或关闭页面会结束当前 Session。手动保存到日历的 Session 持久保存在 IndexedDB 中；报时间隔、准备倒计时和播报模式偏好单独保存。
